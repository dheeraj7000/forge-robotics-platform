# Phase 6: Learned policy with behavioral cloning

This change adds PyTorch-based behavioral cloning to the Forge platform. A new `LearnedPolicy` class implements the existing `Policy` ABC, making a trained neural network a drop-in replacement for the scripted pick-and-place. The training pipeline supports YAML configuration, validation splits, epoch checkpointing, and multi-run dataset loading. A CLI (`forge_train.py`) ties it together with a three-tier config merge (code defaults ← YAML ← CLI). All four design review fixes (YAML-to-flat mapping, model/data config plumbing, empty dataset guard, complete CODE_DEFAULTS) are applied. 149 tests pass, including 32 new tests. Watch for: the `--episodes` and `--demo-policy` CLI flags are silently ignored because they're never added to `cli_overrides` (confirmed), making documented workflows like `--episodes 5` a no-op.

**Verdict**: NEEDS_CHANGES

## High-level view

The config merge system (`CODE_DEFAULTS ← YAML ← CLI`) works correctly for `--epochs`, `--batch-size`, and `--lr`, which use `default=None` and are conditionally added to `cli_overrides`. However, `--episodes` and `--demo-policy` have non-None argparse defaults and are never added to `cli_overrides`, so their CLI values are silently dropped. The code consumes `cfg["episodes"]` and `cfg["demo_policy"]` from the merge result, which never sees the CLI values. This means `forge_train.py --episodes 10` collects 3 episodes (from CODE_DEFAULTS), not 10. The README, setup.md, and the script's own docstring all show `--episodes 5` as a primary usage pattern.

The design review's four fixes are applied: `_YAML_TO_FLAT` mapping covers all 11 config keys, `PolicyNetwork` is constructed from merged model config in the CLI, `target_object` flows from config to `collect_demos`/`from_run_dirs`, the empty dataset guard is in `train_bc`, and `CODE_DEFAULTS` lists all keys that participate in the merge.

The README project structure comment says "116 unit tests" but there are now 148 unit tests.

## Dead CLI flags in the config merge

In `forge_train.py`, the config merge follows a clean pattern for training hyperparameters: `--epochs`, `--batch-size`, and `--lr` all use `default=None` in argparse and are conditionally added to `cli_overrides`:

```python
if args.epochs is not None:
    cli_overrides["epochs"] = args.epochs
if args.batch_size is not None:
    cli_overrides["batch_size"] = args.batch_size
if args.lr is not None:
    cli_overrides["lr"] = args.lr
```

But `--episodes` and `--demo-policy` don't follow this pattern. They have non-None defaults (`3` and `"scripted_pick_and_place"`) and are never placed into `cli_overrides`. Later, the code uses `cfg["episodes"]` and `cfg["demo_policy"]` — values that come from CODE_DEFAULTS or YAML, never from the CLI:

```python
print(f"\nCollecting {cfg['episodes']} demo episodes for '{args.task}'...")
demo_policy = create_policy(cfg["demo_policy"])
dataset = collect_demos(
    task_name=args.task,
    policy=demo_policy,
    n_episodes=cfg["episodes"],
    ...
)
```

The fix is mechanical: change both defaults to `None`, add them to `cli_overrides`, and keep the existing `args.episodes` default as the CODE_DEFAULTS entry (which it already is). No existing test catches this because `TestConfigMerge` tests the `merge_training_config` function directly with explicit arguments — the function works correctly, but the CLI never feeds user values into it for these two flags.

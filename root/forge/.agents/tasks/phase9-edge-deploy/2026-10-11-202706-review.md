# Edge deployment: ONNX export, TensorRT optimization, edge inference runtime

Phase 9 adds a complete edge deployment pipeline to the Forge platform: exporting trained PyTorch policies to ONNX, optional TensorRT optimization for NVIDIA hardware, three Policy ABC implementations for edge inference (OnnxPolicy, TensorRTPolicy, EdgePolicy auto-selector), deployment packaging with YAML manifests, and a full CLI. The implementation follows the project's established patterns — lazy imports for optional deps, YAML-driven config, file-based storage, zero ROS dependency in forge_core/. Watch for: nothing blocking; the implementation is clean and complete across all review criteria.

**Verdict**: APPROVED

## High-level view

The core module `edge_deploy.py` is well-structured: runtime detection helpers at the top, config dataclasses, then the exporter, optimizer, three policy classes, packager, and registry integration. All onnx/onnxruntime/tensorrt imports are lazy — inside `__init__`, method bodies, or guarded behind `has_*()` checks. The module-level imports are limited to numpy, stdlib, and forge_core's own Policy ABC and config utilities.

TensorRT handling is correct throughout. It's absent from `pyproject.toml`'s `[edge]` extra, detected at runtime via `has_tensorrt()`, and every code path that touches it either checks availability first or raises `RuntimeError` with a clear message. EdgePolicy's fallback chain (TRT files + TRT available → TensorRT, else ONNX files → ONNX, else error) is the right design.

The test suite covers the full surface: export, structural validation, numeric equivalence, all three policy classes, packaging, registry integration, and the create_policy factory paths. TensorRT-unavailable paths are tested via `skipif(has_tensorrt())` markers, and ONNX-dependent tests gate on `has_onnxruntime()`. The CLI exposes all six required actions as mutually exclusive flags with appropriate per-action argument validation.

## Policy ABC compliance and type annotations

OnnxPolicy, TensorRTPolicy, and EdgePolicy all subclass `Policy` and implement `reset()`, `act()`, `done`, and `name`. The `act()` and `reset()` methods on the edge policies use `sim: Any` instead of `sim: ForgeSimulation` in their type annotations — a cosmetic divergence from the ABC signature that makes static type checkers less useful on these methods. Runtime behavior is unaffected.

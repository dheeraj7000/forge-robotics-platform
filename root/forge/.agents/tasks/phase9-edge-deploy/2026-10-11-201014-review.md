# Edge Deployment: ONNX export, TensorRT optimization, edge inference runtime

Phase 9 adds a self-contained edge deployment pipeline to the Forge robotics platform. The change introduces `forge_core/edge_deploy.py` with ONNX export, optional TensorRT optimization, three Policy ABC implementations (OnnxPolicy, TensorRTPolicy, EdgePolicy), deployment packaging with manifest generation, and benchmarking utilities. Integration touches the policy factory, runner, eval CLI, and a new deployment CLI. All heavy imports (onnx, onnxruntime, tensorrt) are lazy; TensorRT is runtime-detected and never a pip dependency. The module follows existing project conventions closely.

## High-level view

The core module is well-structured. OnnxExporter handles export and numeric validation against the PyTorch source within a configurable tolerance (default 1e-5, 10 samples). OnnxPolicy / TensorRTPolicy / EdgePolicy all implement the Policy ABC with the standard reset/act/done/name interface, and EdgePolicy auto-selects the best available runtime with a clean fallback chain. TensorRT is fully guarded — never imported at module level, never a pip dependency, raises RuntimeError early when unavailable.

The deployment CLI (`forge_deploy.py`) exposes six mutually exclusive actions covering the full lifecycle: export, validate, benchmark, package, optimize, and registry export. The eval CLI gains `--onnx-model` for direct ONNX evaluation, and the policy factory adds `onnx` and `edge` as lazy-import policy names.

Tests are thorough at 38 cases across 14 classes, covering ONNX export, validation, inference, packaging, and registry integration. TensorRT-unavailable paths are tested with correctly inverted skipif markers. One gap: `TensorRTConfig.__post_init__` rejects invalid precision values, but no test exercises this validation.

The `docs/setup.md` file has corrupted markdown in the two Phase 9 code blocks — backtick fences were replaced with backslashes, making the code blocks unrenderable.

## Corrupted markdown in setup.md

Lines 76–78 of `docs/setup.md` read:

```
\ash
pip install -e '.[edge]'
\
This adds \onnx\ and \onnxruntime\.
```

The same pattern repeats at lines 360–377 for the Edge Deployment usage section. The backtick triple-fences were replaced with single backslashes, and the inline backtick-quoted package names `onnx` and `onnxruntime` became bare backslash-escaped text. This makes both code blocks unrenderable in any markdown viewer. The rest of the documentation (architecture.md, README.md) is clean.

## TensorRTConfig validation gap

`TensorRTConfig.__post_init__` explicitly validates that `precision` is one of `"fp16"` or `"fp32"`, raising `ValueError` otherwise. The test suite covers default values and `fp16`, but never exercises the rejection path. This is a minor testing gap — the validation logic is three lines and clearly correct, but the project's pattern is to test error paths (e.g., `test_validate_fails_on_bad_tolerance`, `test_init_raises_without_tensorrt`, `test_create_onnx_policy_missing_path_raises`), so the omission is inconsistent.
